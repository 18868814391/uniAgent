# dev-rmslop（清掉 AI 味代码）

改造自 opencode 的 `/rmslop` 命令。针对**模型改码的常见病**：为了「显得稳妥」而堆一批代码库里本来没有的东西。
国产模型尤其容易犯——每次改函数都顺手加 `try/catch`、加 `console.log`、加一段「// 这里做 X 处理」的注释。

## 清什么

对照 `git diff`（本次改动的范围），逐条检查：

- **多余注释**：代码库里同位置没有人写注释，你写了；或注释只是把代码翻译成中文
  （`// 设置 loading 为 true` 后面就是 `loading = true`）—— 删。
- **异常防御**：给**受信任/已被上游校验过**的调用路径加 `try/catch` / `if (!x) return` /
  `x?.y ?? default`。改前先看这个函数原本的调用方 —— 上游已经过滤过的，你别再过滤一遍。
- **类型逃逸**：`as any`、`@ts-ignore`、`// eslint-disable` —— 能真修就真修，不能就说明为什么不能。
- **风格不一致**：文件里明明用 `const` 箭头函数，你写成 `function`；明明用单引号，你写双引号；
  明明用 2 空格，你写 4 空格 —— 跟你改的这个文件走，不跟你自己的习惯走。
- **无谓 emoji / 装饰性分隔线**：代码、提交信息、变量名里的 emoji 一律清掉。
- **顺手重构**：你没被要求动的代码，不要动。看到旁边有个坏味道想顺手改 —— 忍住，或者单独提出来问。

## 不清什么

- **不是你这次改的存量代码** —— 那是另一个任务，不要混进本次 diff。
- **项目本身就有的一致性防御**：如果整个文件/模块每个导出函数都做入参校验，你加的校验就保留。
- **确有必要的边界检查**：外部输入（用户输入、网络响应、文件内容）的校验是应该的，别误删。

## 流程

1. `git diff <改动的文件>` 拿到本次改动全文（若已暂存，`git diff --cached`）。
2. 逐文件扫上面那张清单，定位到**多余的**那几行。
3. `edit_file` 精准删除 / 改写。只动多余的，不要顺带重排格式（会产生巨型假 diff）。
4. 改完复跑一次 `git diff` 确认 diff 缩干净了、没误删必要逻辑。
5. 自检按 `dev-self-check`（语法检查按目录跑）。

## 汇报

**只给 1~3 句**：清了哪几类、涉及哪几个文件。不要逐条罗列删了多少行。

```
清理：删掉 3 处翻译式注释、2 处上游已校验过的重复判空、1 处 as any；
涉及 electron/tools/foo.js、src/views/bar.vue。未动存量代码。
```

## 边界

- 本技能是**收尾清理**，不替代 `dev-code-change` 主流程，也不替代功能正确性。
- 清完仍要能跑 —— 删防御性检查前，确认那条路径真的被上游兜住了，别把真防御当冗余删了。
