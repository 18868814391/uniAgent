# legal-contract-review（合同审查）

用户给一份合同 / 协议要求"审查、找问题、提修改"时启用。

## 流程

0. **确认审查范围（范围前置，长合同必做）**：用户只说"看看这份合同 / 审查一下"没指定重点时，先用 `legal-ask`（`ask_user` 工具）让用户点选审查重点——`付款与发票` / `违约责任与解除` / `保密与知识产权` / `数据与合规` / `争议解决与管辖` / `全量逐条`。确认范围后再进入逐条核查，并在产物头部写明「本次审查范围」，**未覆盖部分不视为无风险**。全量逐条只用于短合同或用户明确要求。
1. **读合同**：`read_file` 用户提供的合同文件（授权目录内），必要时 `legal-clause-extract` 先抽条款清单。
2. **逐条核查**：围绕以下维度逐条给出判断：
   - 主体资格 / 签约权限是否清晰
   - 标的、数量、质量、价款 / 报酬是否明确
   - 履行期限、地点、方式、验收是否可执行
   - 违约责任、赔偿、定金 / 违约金是否合理
   - 保密、知识产权、合规（数据 / 反垄断 / 行业监管）条款
   - 争议解决（诉讼 / 仲裁管辖）是否有利
   - 与现行法律（`{{CODE_REPO_DIR}}` 检索）是否冲突
3. **给修订建议**：每条问题附「风险说明 + 建议改法 + 法律依据（引用条号）」。
4. **成稿**：落 `{{LEGAL_OUTPUT_DIR}}/<任务slug>-合同审查.md`，末尾附免责声明（`{{HARNESS_CONVENTIONS_DIR}}/legal/disclaimer.md`）。

## 边界

- 内部合同**只读本地、禁止联网**（见 `confidentiality.md`）。
- 合同为扫描件 / 图片型 PDF（文本层抽不到字）时，如实告知「疑似扫描件，无法读取文字内容，需先 OCR 或提供可编辑文本版本」，**不得假装读取到内容**继续输出条款判断。
- 不臆造事实：缺失信息标 `TODO: 人工确认`，用 `legal-ask` 向用户澄清关键空白（金额、期限、主体）。
- 结论三档：文本可证 / 需人工确认 / 需执业律师裁定。
