# legal-ask（澄清反问）

法务任务常因事实缺失而无法推进，本技能规范如何向用户澄清。

## 何时反问

- 任务目标不清（"帮我看看这份合同"→ 是审查 / 抽条款 / 标风险 / 起草？）
- 关键事实空白：主体名称、金额 / 期限、标的、适用法律、争议管辖未知且影响结论。
- 需要在多个方向 / 方案间让用户拍板。

## 怎么反问

- **调用 `ask_user` 工具**（函数调用）提一个简短问题或给 ≤6 个选项，应用会弹出可点选卡片；**严禁用纯文字列出选项**——那样只是显示文字、用户无法点选，对话会卡住。参数：`question`（字符串）+ `options`（≤6 个字符串，可省略为开放式输入）。
- 能推断的先给判断让用户确认（如"我先按'审合同付款条款'处理，对吗？"），不要把所有问题都推回。
- 同一信息已问过不再重复；单个对话轮次内连续反问不超过 3 次。
- 用户回答后基于已有信息推进，仍未确认的项标 `TODO: 人工确认`，不臆造。

示例：

```
ask_user(
  question: "本地库未收录该法规，是否授权我去国家法律法规数据库官网检索？",
  options: ["是，去官网搜全文", "只搜具体条文", "不需要，我另有途径", "咨询执业律师"]
)
```

> 查**明确公开法规**默认免问直达：直接调用 `legal_npc_search` 工具去官网（https://flk.npc.gov.cn/）精确检索，勿用通用 `search_web`（详见 `ask-user-rules.md`「默认策略」）；仅在对象疑似涉密 / 意图不明时才经 `ask_user` 确认。

## 边界

- 不借反问套取用户不想给的涉密信息；用户拒绝提供时，按"信息缺失"标注并继续可做的部分。
