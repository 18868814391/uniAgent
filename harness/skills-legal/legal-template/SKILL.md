# legal-template（文书草拟）

用户要求"起草函件 / 协议 / 通知书 / 制度 / 声明"时启用。

## 流程

1. **澄清要素**：用 `legal-ask` 确认关键空白——主体名称、标的、金额 / 期限、双方权利义务、适用法律与管辖。缺失且影响效力的，必须 `TODO: 人工确认`，不臆造。
2. **草拟**：按用户行业惯例与现行法律（`{{CODE_REPO_DIR}}` 检索相关条文）组织结构：
   - 协议类：首部（主体）→ 鉴于条款 → 标的 / 价款 → 履行 → 违约 → 保密 / 知识产权 → 争议解决 → 附则。
   - 函件类：事由 → 事实依据 → 主张 / 要求 → 期限 → 落款。
3. **占位符**：未知项用 `【】` 或 `< >` 标注（如 `【甲方全称】`、`<违约金比例>`），并在文末列"待确认事项清单"。
4. **成稿**：落 `{{LEGAL_OUTPUT_DIR}}/<任务slug>-草拟稿.md`，末尾附免责声明（`{{HARNESS_CONVENTIONS_DIR}}/legal/disclaimer.md`）。

## 边界

- 不替用户做法律结论（如"此条款必然有效"）；效力判断标 `TODO: 执业律师确认`。
- 草稿含当事人信息默认脱敏（见 `confidentiality.md`），交付前由用户填实。
- 内部文书禁止联网检索（防泄密）。
