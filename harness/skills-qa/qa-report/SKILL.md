# qa-report（测试报告生成）

## 适用

- 白盒逐条核对完成、黑盒操作结束、或用户要求测试总结/质量复盘时。
- 输出正式测试报告（`{{TEST_OUTPUT_DIR}}/<任务slug>-测试报告.md`）。

## 输入收集

- 白盒：`qa-case-ledger` 台账 + `qa-whitebox-review` 核对日志。
- 黑盒：步骤回放记录 + `browser_console_logs` 证据。
- 用户补充的测试用例原文、预期、缺陷列表（若提供）。
- 缺失的元信息（人员、时间、环境、未覆盖范围）标 `TODO: 人工确认`，不编造。

## 生成流程

1. **结论前置**：先写测试结论（判定状态 + 覆盖统计 + 关键问题数 + 风险一句话），再给支撑数据。
2. **按 `report-contract.md` 固定章节**输出：结论 → 范围与输入 → 关键问题 → 风险汇总 → 详细结果 → 用例覆盖台账 → 附录。
3. **统计口径统一**：通过 / 失败 / 未执行 / 仍需联调 / 无法静态验证；通过率分母在报告中写明。
4. **对账**：对照台账确认无「未核对」的原始用例；覆盖不完整则先补测再出报告。
5. 写文件到 `{{TEST_OUTPUT_DIR}}/<任务slug>-测试报告.md`（目录不存在自动创建父目录），向用户汇报**绝对路径**。

## 报告质量要求

- 每条详细结果有代码/页面证据，标注数据来源（用例 / 核对日志 / 控制台 / 人工确认）。
- 结论与数据一致：判定「通过」则关键问题数为 0。
- 未闭环缺陷、未执行用例、无法验证范围必须进入风险/遗留项，不静默删除。
- 输出后自检是否覆盖报告模板全部固定章节。
