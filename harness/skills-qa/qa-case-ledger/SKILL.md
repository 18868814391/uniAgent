# qa-case-ledger（用例拆解与覆盖台账）

## 适用

- 白盒测试拿到用例后、逐条核对代码前，先建台账。
- 用例较长或跨模块时，先通读再拆分。

## 步骤

1. **通读并拆模块**：按功能能力、端（前端/后端）、主链路、导出/审批/状态流转等边界拆分模块；每条用例必须落入某个模块，不清楚的放「范围识别 / 待确认」。
2. **建立原始用例台账**：保留原始用例编号与标题；原文没有编号时按出现顺序生成 `QA-TC-001`、`QA-TC-002`…。台账字段：`编号 | 原始标题/描述 | 模块 | 核对批次 | 状态`。
3. **分批计划**：普通流程每批约 10~15 条用例，字段密集型按表单拆批，跨端/RPC 副作用链路每批 5~8 条。每批开始前明确本批核对重点。
4. **覆盖对账**：每批核对完成后对照台账做覆盖对账；发现未核对/待补测用例，必须继续补测，**不允许带着「未核对」进入最终报告**。仓库缺失或运行时数据导致的无法闭环，归入「仍需联调 / 无法静态验证」，不算未核对。

## 输出

- 台账文件：`{{TEST_OUTPUT_DIR}}/work/<任务slug>/case-ledger.md`（过程产物）。
- 台账结构供 `qa-whitebox-review` 逐批消费、`qa-report` 汇总统计。
