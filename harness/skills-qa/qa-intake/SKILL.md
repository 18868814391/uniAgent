# qa-intake（任务入口与范围确认）

## 硬性闸门（先过这一关，不满足就退出）

先判型：本条消息若属于**询问/核对既有系统逻辑**——用户在问系统现在怎么运作、为什么这样、有哪些状态、是否允许某操作、某字段或校验口径，而没有「出测试报告 / 跑用例 / 白盒审查某段代码」的委托诉求——**不要进入本技能**。直接读用户提供的代码目录讲解清楚；禁止 `ask_user` 反问用例与路径、禁止触发克隆仓库与权限预置。若拿不准方向，先给判断并最多用一次 `ask_user` 确认「解释现有逻辑 vs 进入测试」，再决定是否继续本流程。

## 适用

- 用户发起任何「测试 / 核对 / 审查」类任务的起点。
- 用户说「测试某功能 / 帮我校对下用例 / 做白盒测试」但范围、代码路径、用例不明确时。

## 输入确认清单

1. **被测代码路径**：
   - 用户提供路径后，先用 `list_directory` / `read_file` 确认可读、存在。
   - 被测代码**固定为应用已自动拉取的开发仓库**（随运行平台变化）：
     - **ERP**：前端 `{{CODE_REPO_DIR}}`（`{{CODE_REPO_DIR}}`）、后端 `{{CODE_REPO_DIR}}`（`{{CODE_REPO_DIR}}`）。
     - **其它系统**：前端 `{{CODE_REPO_DIR}}`（`{{CODE_REPO_DIR}}`）、H5 `{{CODE_REPO_DIR}}`（`{{CODE_REPO_DIR}}`）、后端 `{{CODE_REPO_DIR}}`（`{{CODE_REPO_DIR}}`）。
   - 目录缺失/不是 git 仓库时，提示用户在代码仓库浮窗点「立即拉取」或重新切换一次测试身份，**不尝试绕过、不臆测**。
   - **禁止用 `{{CODE_REPO_DIR}}` 知识库的 源代码目录/源代码目录 或线上后端网关代码当作被测对象**——那是脱敏正式环境代码，与开发分支可能不一致（且 MES 平台根本没有知识库）。若用户给的路径指向了知识库，先引导其改为 `{{CODE_REPO_DIR}}` 下的开发仓库。
2. **测试用例来源**：
   - 优先用户给出用例文件路径（`read_file` 读取）。
   - 或用户直接描述用例/预期；描述不完整时用 `ask_user` 补问关键边界，不自行假设。
3. **测试类型**：白盒（代码路径 + 用例 → 源码审查）/ 黑盒（用户明确打开页面并引导）。
4. **输出位置**：默认 `{{TEST_OUTPUT_DIR}}/<任务slug>-测试报告.md`，用户指定则按用户要求。

## 流程

1. 复述理解的任务范围，缺项用 `ask_user` 一次补齐 2~3 个关键信息。
2. 确认路径可读后，输出一份简短的「范围确认」小结（被测对象、用例数、测试类型、输出位置），再进入 `qa-case-ledger`。
3. 范围不清时**不要直接开始读代码**，先确认再动手。

## 输出

- 一段简短范围小结（不落文件，供确认）；进入下一环节时告知用户当前环节。
