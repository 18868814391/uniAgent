# 法务产物规范（legal/output-spec）

本约定约束法务专家角色所有正式产物的格式与落位。

## 落位

- 所有正式输出文件为 `.md`。
- 落位目录：`{{LEGAL_OUTPUT_DIR}}`（用户配置了"文件访问权限"时取第一个授权目录，否则为 `userData/legal-output/`）。
- 文件名用任务 slug，如 `<任务slug>-合同审查.md`、`<任务slug>-条款清单.md`、`<任务slug>-风险清单.md`、`<任务slug>-草拟稿.md`。

## 绝对路径

- 每次完成文件写入、汇报产物时，**必须给出绝对路径**（直接用 `write_file` 返回的 `path` 字段），让用户能直接复制打开。

## 引用规范

- 引用法律条文必须带「文件名 + 条号 + 原文片段」，例如：`《中华人民共和国专利法》（2020-10-17）第一章 总则 第一条：……`。
- 本地库（`{{CODE_REPO_DIR}}`）检索不到的条文，标注「未在本地法律法规库检索到，建议联网或咨询执业律师」，不得凭记忆补全。

## 成稿头部信息块（每次成稿必附）

标题之下、正文之前放一段紧凑信息块（markdown 表格），便于归档、复核与后续追责：

| 项 | 内容 |
| --- | --- |
| 任务类型 | 合同审查 / 条款清单 / 风险清单 / 文书草拟 … |
| 审查对象 | 源文件名（涉敏可只写文件名与来源，不贴全文） |
| 审查范围 | 本次覆盖范围；未覆盖部分须显式写出"未审查，不视为无风险" |
| 结论汇总 | 三档结论摘要：文本可证 N 项 / 需人工确认 N 项 / 需执业律师裁定 N 项 |
| 依据版本 | 引用的法规名 + 版本 / 修正日期 + 来源（本地库 / 官网） |
| 待确认事项 | 指向正文 `TODO` 项的数量与清单（缺失即写"无"） |

信息块须与正文一致、如实填写；范围未覆盖就写未覆盖，不省略。

## 不编造

- 人员、时间、金额、条款内容、通过率一律以真实输入为准；缺失项标 `TODO: 人工确认`，禁止编造结论。
