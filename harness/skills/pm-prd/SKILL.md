# pm-prd（PRD 成稿）

## 适用

- 需求已澄清、原型已对齐代码，需要沉淀正式 PRD。
- 用户要求"写 PRD / 输出需求文档 / 成稿"。

## 前置条件

正式 PRD 只承接**已确认或已收敛**的内容。以下情况只能输出草案/确认稿：
- 关键流程、状态、权限、字段未确认。
- 原型设计未完成或未对齐代码。

## 步骤

1. 读取上游产物：`{{PRODUCT_OUTPUT_DIR}}/work/<任务slug>/` 下的澄清卡、原型设计、字段逻辑表。
2. 标记 `【已确认】/【推断】/【待确认】`。
3. 按 output-spec.md 的 PRD 结构成稿。
4. 承接原型设计与 UI 对齐结论，不重新发明范围。
5. 正式 PRD 写入 `{{PRODUCT_OUTPUT_DIR}}/<任务slug>-PRD.md`。

## 结构（见 output-spec.md）

背景与目标 / 范围（In & Out of scope）/ 功能需求（含业务规则）/ 页面与交互（承接原型）/ 数据字段与业务规则（字段逻辑表 + 状态机 + 校验）/ 权限与角色 / 已确认·推断·待确认 / 风险与依赖

## 强制规则

1. UI 样式、组件名、颜色尺寸不写进业务规则（那是原型/前端的事）。
2. 未确认接口契约不写成既定事实。
3. 关键流程、状态、权限、字段未确认时，只能输出草案或确认稿。
4. 不把原型里的临时实现/占位逻辑写成最终业务规则。
5. 命中编号、人员、时间、金额、状态、表格、筛选、表单、详情、审批、导入导出等规则对象时，必须承接 global-product-rules.md。
